# 商业化开关与支付预埋 — 设计说明

> 原则：**先验证，再商业化**。面试结束或内测满 10 人之前，任何付费入口都不可见、不可调。

---

## 1. 触发条件（任一满足即"允许开启"）

| 触发项 | 判定方式 |
|---|---|
| ① 面试已结束 | 环境变量 `INTERVIEW_END_AT=YYYY-MM-DD`，系统日期 ≥ 该日期 |
| ② 有效内测用户 ≥ 10 | `users.status='approved'` 且 30 天内有过 `metrics` 记录 |

### 「有效内测用户」定义（三条同时满足）

1. 完成注册（写入 `users` 表）
2. 通过管理员审核（`status='approved'`）
3. 实际发生过至少 1 次有效对话（`metrics` 表 30 天内有记录）

---

## 2. 开关说明

- **`commercialization.COMMERCIALIZATION_ENABLED`**：布尔值，默认 `False`
- 即使触发条件满足，开关也**不会自动打开**——必须管理员手动调 `enable()`
- `enable()` 内部会再校验一次触发条件，不满足直接拒绝
- `disable()` 可紧急关停

### 谁有权限开启

当前是单机 MVP，管理员就是开发者本人（环境变量 + 直接调函数）。
生产级应该加一个 `is_admin` 中间件，只有 admin token 才能调 `/api/admin/commercialization/enable`。

---

## 3. 支付渠道配置（沙箱/正式切换）

| 环境变量 | 说明 |
|---|---|
| `PAYMENT_PROVIDER` | `mock`（沙箱，默认）/ `wechat` / `alipay` |
| `PRICE_PER_CHAT` | 单次价格，默认 0.5 元 |
| `PRICE_MONTHLY` | 月费，默认 19.9 元 |
| `PAYMENT_WECHAT_MCH_ID` | 微信商户号（正式期填） |
| `PAYMENT_WECHAT_API_KEY` | 微信 API 密钥（正式期填） |
| `PAYMENT_WECHAT_NOTIFY_URL` | 微信回调地址 |
| `PAYMENT_ALIPAY_APP_ID` | 支付宝 APPID |
| `PAYMENT_ALIPAY_PRIVATE_KEY` | 支付宝私钥 |
| `PAYMENT_ALIPAY_NOTIFY_URL` | 支付宝回调地址 |

**切换流程**：触发条件满足 → 管理员在商户平台申请好资质 → 填环境变量 → `PAYMENT_PROVIDER=wechat` → 重启 → 切沙箱测试一笔 → 切正式。

---

## 4. 防御校验

所有付费接口在函数入口第一行就调：
```python
from app.commercialization import assert_commercialization_on
assert_commercialization_on()  # 开关关闭直接 RuntimeError
```
包括：`create_order`、未来的 `refund`、`query_my_orders`。

---

## 5. 前端入口控制

前端启动时拉 `GET /api/config`，拿到 `commercialization` 字段：

| 字段 | 关闭时 | 开启时 |
|---|---|---|
| `show_pricing` | false | true |
| `show_buy_button` | false | true |
| `show_subscribe_entry` | false | true |
| `pricing` | null | 价格表 |

**关闭时前端必须把这些节点全部隐藏，不能只禁用按钮**——避免设计稿泄露定价。
